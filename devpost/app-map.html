Perceptron — App Map

Where everything lives, drawn from the finished code. Start at the top left (browser) and follow a tap to the right (Flask) and back.

The request path — one tap through the app

frontend/src/components/AnswerCard.vueVue
  • A big tappable option. Sets store.selected; nothing is judged yet.
frontend/src/components/PracticeScreen.vueVue
  • The core loop screen: question + Read aloud, answers, Check, Hint, Take a break. Shows the verdict state (soft green / lavender / revealed).
frontend/src/store.jsVue
  • One reactive object holding honey, level, dyslexia, the current question — plus the actions (submitAnswer, startPlacement, restoreSession…) that call api.js. No Pinia, on purpose.
frontend/src/api.jsVue
  • Every fetch('/api/...') in one module; maps error codes (unknown_question, unknown_device…) to friendly sentences.
backend/app.pyFlask
  • Routes + validation: /api/session, /api/placement/*, /api/practice/question, /api/check, /api/hint, /api/preferences, /api/reset. One error envelope {error:{code, description}}, never a stack trace. Serves frontend/dist in the single-process demo.
backend/questions.pyFlask
  • The referee: grades answers, advances hints (nudge → first step → worked example → reveal), awards 5/3/0 honey against the daily cap, picks unseen questions and recycles the bank. Correct answers never leave here before you submit.
backend/state.pyFlask
  • SQLite only: students, placement_answers, seen_questions, attempts. Every query parameterized. Created automatically on first run.
backend/data/fractions.jsonContent
  • 6 placement + 28 practice questions, each with three authored hints and an explanation. Malformed entries are skipped at load; the count prints at startup.

The kernel — where the accessibility promise lives

frontend/src/speech.jsVue
  • Read aloud: each word spoken as its own utterance, highlighted before it speaks; stops on Check/Next; friendly fallback when the browser can't speak.
frontend/src/components/DyslexiaPanel.vue + main.jsVue
  • One switch flips data-dyslexia on <html> — font, spacing, size and motion change together via CSS variables in styles/base.css — and posts the preference so it survives refresh.
frontend/src/components/BreakOverlay.vueVue
  • Full-screen calm card, breathing circle, no timer; Keep going returns to the exact question. Reduced motion = static circle, text only.

Rules worth remembering (reusable practice)

  • The server owns the truth. Grading, honey, caps and hint progression live in Flask; the client only asks. Reward idempotency is keyed to the attempt row, so double-taps can't double-pay.
  • Dates you didn't generate are lies until checked. The client's "today" is only honored inside the ±1-day window any real UTC offset could produce — a forged date can't reset the cap.
  • One error shape everywhere. Every failure is {error:{code, description}}; the frontend maps codes to friendly text, so users never see a stack trace.
  • Small slices beat big plans. This shipped as eight end-to-end slices, each verified (curl walks, then Playwright) before the next began.

Try this next time: before writing any handler, write its failing-request tests first — bad selection, unknown question, unknown device, forged date. The four corrections that shaped this app all came from asking "what if the client lies?"
